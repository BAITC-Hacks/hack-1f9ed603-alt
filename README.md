# Прогноз выработки ВЭС

Каркас решения HackAlem AI: почасовой прогноз нормализованной активной мощности двух турбин на 24–48 часов. Сейчас работают API, интерфейс и чтение исходных CSV. Прогнозная модель и архивные погодные прогнозы ещё не подключены; API сообщает об этом явно.

## Структура и ответственность

| Папка | Владелец | Задача |
| --- | --- | --- |
| `backend/` | Участник 1 | HTTP API, валидация, хранение запусков, вызов прогнозного ядра |
| `frontend/` | Участник 2 | Интерфейс, графики, сценарий пользователя |
| `forecasting/` | Участник 3 | Подготовка данных, архив погоды, модель, последовательная проверка |
| `shared/` | Согласованно | Контракт API; изменения обсуждаются перед коммитом |
| `data/raw/` | Участник 3 | Исходные CSV без правок |

Все работают в `main`, каждый изменяет файлы своей папки. `README.md`, `shared/`, `.env.example` и `compose.yaml` ведёт участник 1 после согласования с остальными. Перед началом работы и перед пушем выполняйте `git pull --rebase`; коммитьте только свои файлы. Не используйте `git add -A`, если в рабочей копии есть изменения других участников.

## Данные и временная граница

`data/raw/turbine_1.csv` и `data/raw/turbine_2.csv` — предоставленные организаторами десятиминутные наблюдения с 2023-03-11 по 2026-01-31 включительно. Февраль 2026 — тестовый период, его фактической выработки в комплекте нет. Время в CSV не содержит часового пояса; до его подтверждения нельзя молча считать метки UTC. Цель — нормализованная мощность от 0 до 1; перевод в абсолютные кВт·ч требует номинальной мощности турбин.

При воспроизведении февральских прогнозов на момент каждого запуска допускается только прогноз погоды, уже опубликованный к этому моменту. Фактическая погода за будущие часы и архивный ряд, составленный из поздних модельных запусков, приведут к утечке будущего. Выбор источника и точная проверка времени выпуска прогноза — задача владельца `forecasting/`.

## Локальный запуск

Требуются Python 3.11+ и Node.js 20.19+.

```powershell
# Из корня проекта, терминал 1
python -m venv .venv
.\.venv\Scripts\python -m pip install -r backend\requirements.txt
.\.venv\Scripts\python -m uvicorn backend.app.main:app --reload --port 8000

# Терминал 2
cd frontend
npm ci
npm run dev
```

На macOS/Linux используйте `.venv/bin/python` и `/` в путях. Интерфейс: http://localhost:5173, API: http://localhost:8000/docs. Vite проксирует `/api` к `http://localhost:8000`; адрес можно изменить через `VITE_API_PROXY_TARGET`.

Docker-вариант: `docker compose up --build` из корня проекта. В нём исходные CSV монтируются в контейнер API без записи.

## API и готовность

- `GET /api/health` — состояние сервиса.
- `GET /api/turbines` — статистика чтения исходных файлов.
- `POST /api/forecast-runs` — контракт запуска прогноза. Пока возвращает HTTP 501 с понятной ошибкой; подключается после реализации `forecasting/`.

Контракт запросов и ответов описан в `shared/API.md`. Корректность чтения CSV можно проверить командой `python -m forecasting.inspect_data` из корня проекта.

## Ближайшая реализация

1. Подтвердить координаты, часовой пояс CSV и источник архивных прогнозов с временем выпуска каждого запуска.
2. Агрегировать десятиминутные наблюдения в часы, сохраняя признак неполных часов и длинных пропусков.
3. Обучить простой проверяемый базовый прогноз, затем сравнить с более сложной моделью на временных срезах до февраля 2026 года.
4. Связать `POST /api/forecast-runs` с ядром, добавить сохранение параметров, версии модели, погодного выпуска и результата.
5. Провести последовательную проверку запусков за февраль без использования будущих данных.
