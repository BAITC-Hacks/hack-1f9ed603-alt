# Почасовой прогноз выработки ВЭС

Проект HackAlem AI строит прогноз нормализованной активной мощности двух ветровых турбин на 24 или 48 часов с шагом один час. Пользователь выбирает турбину, момент запуска и горизонт, а система получает подходящий архивный прогноз ветра, применяет обученную модель и показывает почасовой результат вместе с происхождением погоды и версией модели.

**Текущее состояние:** основной сценарий работает для поддерживаемых исторических запусков. Например, запрос на `2026-02-01T12:00:00Z` возвращает 24 или 48 точек через API и отображается в интерфейсе. Последовательный расчёт для всего февраля и отдельная модель для запуска 31 января ещё не готовы; конкретные задачи перечислены в [TASKS.md](TASKS.md).

## Как устроено

```text
Браузер (React) → FastAPI → forecasting.runner → модель кривой мощности
                    │                 └→ архивный прогноз ветра ECMWF IFS
                    └→ SQLite с успешными запусками
```

| Папка | Ответственность |
| --- | --- |
| `backend/` | HTTP API, валидация, проверка временных границ, сохранение успешных запусков |
| `frontend/` | Выбор параметров, график и таблица почасового прогноза, ошибки |
| `forecasting/` | Подготовка часовых рядов, погодный архив, обучение и расчёт модели |
| `data/raw/` | Два исходных CSV, выданных организаторами |
| `data/processed/` | Часовые ряды, манифест исторических запусков и отчёт проверки |
| `data/weather/` | Сохранённые ответы архива погоды |
| `shared/API.md` | Формат запросов и ответов между участниками |

Команда работает в одной ветке `main` по папкам: backend и общая интеграция, frontend, forecasting и данные. Перед пушем каждый делает `git pull --rebase` и добавляет в коммит только свои файлы.

## Данные и модель

Исходные CSV содержат десятиминутные наблюдения двух турбин с 11 марта 2023 года по 31 января 2026 года. Февраль 2026 года — период исторического воспроизведения прогнозов; фактических значений мощности за февраль в репозитории нет. Целевая величина находится в диапазоне 0–1 и не является кВт·ч.

Подготовка данных формирует часовую сетку и сохраняет пропуски. Для обучения используются только полные часы с известной мощностью. Текущая базовая модель — сглаженная зависимость мощности от прогнозной скорости ветра на высоте 100 м. Прогнозы ветра взяты из отдельных архивных запусков ECMWF IFS через [Open-Meteo Single Runs](https://open-meteo.com/en/docs/single-runs-api); код выбирает выпуск, инициализированный не позже чем за 12 часов до расчёта. Время инициализации модели погоды не равно подтверждённому времени её публикации — это ограничение явно сохраняется в манифесте и описано в [forecasting/README.md](forecasting/README.md).

Для текущих подготовленных файлов использовано явное рабочее смещение времени CSV `+05:00`. Это параметр подготовки, зафиксированный в артефакте модели. Исторические запуски декабря 2025 и января 2026 проверены последовательно: модель обучалась только на более ранних примерах. Отчёт с MAE и сравнением с простыми базовыми прогнозами находится в [data/processed/backtest_report.json](data/processed/backtest_report.json). Ошибку за февраль по предоставленным файлам вычислить нельзя.

## Запуск

Нужны Python 3.11+, Node.js 20.19+ и доступ к интернету для погодных выпусков, которых нет в локальном кэше. Ключ API для текущего погодного источника не требуется.

### Локально

В первом терминале, из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r backend\requirements.txt
.\.venv\Scripts\python -m uvicorn backend.app.main:app --reload --port 8000
```

На macOS/Linux используйте `.venv/bin/python` и прямые слеши в путях. Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Документация API: http://localhost:8000/docs. Vite проксирует `/api` к `http://localhost:8000`; адрес меняется через `VITE_API_PROXY_TARGET`.

### Docker

```bash
docker compose up --build
```

Исходные CSV монтируются в контейнер backend без записи. Сохранённые погодные выпуски монтируются из `data/weather/ecmwf_ifs/`; новые выпуски backend может добавить в эту папку через внешний API, поэтому для дат вне кэша нужна сеть. Успешные расчёты хранятся в именованном томе `runs_data` и сохраняются при пересоздании контейнера.

### Повторить подготовку и проверку модели

```bash
python -m forecasting.train_baseline --csv-utc-offset +05:00
python -m unittest discover -s forecasting/tests -v
python -m unittest discover -s backend/tests -v
cd frontend && npm ci && npm run build
```

Команда обучения использует локальный погодный кэш и запрашивает отсутствующие выпуски у Open-Meteo. Подробности и ограничения методики — в [forecasting/README.md](forecasting/README.md).

## Проверить основной сценарий

1. Откройте интерфейс и убедитесь, что отображаются обе турбины и количество наблюдений.
2. Выберите турбину 1, горизонт 48 часов и введите `2026-02-01T12:00:00Z`.
3. Нажмите «Запустить». Ожидаемый результат — график и таблица из 48 значений, время погодного выпуска, идентификатор погодного запуска и версия модели.

Тот же запрос через API:

```bash
curl -X POST http://localhost:8000/api/forecast-runs \
  -H "Content-Type: application/json" \
  -d '{"turbine_id":"turbine_1","issued_at":"2026-02-01T12:00:00Z","horizon_hours":48}'
```

Успех — HTTP 201 и структура из [shared/API.md](shared/API.md). Неверный запрос возвращает 422; отсутствие модели — 501; недоступные данные или погодный источник — 503. Ошибка не подменяется вымышленным прогнозом.

## Известные ограничения

- Финальный артефакт модели обучен с использованием наблюдений 31 января; для запуска прогноза **31 января** нужна отдельная модель, обученная до выбранного момента.
- Полный последовательный расчёт для всех дат февраля пока не автоматизирован.
- Фактическое историческое время публикации погодного выпуска архив не предоставляет; используется консервативное правило доступности через 12 часов после инициализации.
- Положение десятиминутной метки относительно измеряемого интервала неизвестно; код явно использует одно правило агрегации для всех файлов.
- Высота измерения ветра в CSV не указана; прогноз погоды использует скорость ветра на высоте 100 м.
