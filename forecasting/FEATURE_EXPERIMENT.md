# Эксперимент с расширенными архивными погодными признаками

Эксперимент улучшает прогноз нормализованной мощности относительно действующей
биновой модели, но дополнительная погода не даёт устойчивого преимущества над
признаками, рассчитанными из уже имевшегося прогноза ветра. Модель пока не подключена
к API: `forecasting.runner` продолжает использовать baseline.

## Данные и воспроизводимость

- Целевая мощность взята только из выданных `data/raw/turbine_1.csv` и
  `data/raw/turbine_2.csv`. Исходные файлы не изменены и не заменены внешними данными.
  Используются средние полных часов из шести десятиминутных записей; неполные часы
  исключаются. Контрольные суммы CSV сохранены в отчёте.
- Сохранено правило `as_provided_no_shift`: календарные метки CSV сопоставляются
  одноимённым меткам оси прогноза без прибавления или вычитания часового пояса.
- Дополнительные признаки получены из 92 отдельных запусков ECMWF IFS через
  [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api),
  ежедневно в 00:00 UTC с 1 ноября 2025 по 31 января 2026. Это архивные **прогнозы**,
  а не фактическая погода будущих часов. Условия атрибуции:
  [Open-Meteo / ECMWF, CC BY 4.0](https://open-meteo.com/en/terms).
- Новый кэш: `data/weather/ecmwf_ifs_features/`. В нём сохранены исходные ответы,
  URL запросов, единицы, профиль признаков и время инициализации. Контрольные суммы
  каждого файла перечислены в отчёте. Скорость ветра на 100 м проверена на точное
  совпадение со старым кэшем на всех используемых часах.
- Запуск прогноза мощности — 12:00 UTC. Используется консервативная доступность
  погодного запуска через 12 часов после инициализации; точное историческое время
  публикации API неизвестно. Производные признаки берутся из того же запуска.

Из архива читаются скорость ветра на 100 и 10 м, направление на 100 м, температура
на 2 м и приземное давление. Направление кодируется синусом и косинусом.
Производные признаки: разница скоростей между высотами, приближённая плотность
воздуха, средняя скорость за текущий и два предыдущих часа прогноза, изменение
скорости за три часа, час суток и дальность прогноза от инициализации.
Плотность — приближение по температуре на 2 м и приземному давлению, не измерение
плотности на высоте ротора. Пропущенная погода не заполняется искусственно.

## Проверка

Обучение отдельно для каждой турбины: ноябрь → декабрь, ноябрь–декабрь → январь.
Целевые часы обучения строго раньше начала проверяемого месяца. В обучение входят
первые 24 часа каждого запуска, как у baseline; проверка проводится на горизонтах
1–24 и 1–48 часов. Повторный расчёт MAE baseline совпал с сохранённым
`data/processed/backtest_report.json` с допуском `1e-10` во всех восьми срезах.

Используется `HistGradientBoostingRegressor` с фиксированными параметрами из
`experiment_features.py`. Перемешивания временных срезов и автоматического
случайного validation split нет. Из первоначальных кандидатов модель выбирается
по минимальной объединённой MAE **декабря**. Январь не используется для выбора.

MAE ниже — средняя абсолютная ошибка нормализованной мощности, меньше лучше:

| Модель / признаки | Декабрь | Январь |
| --- | ---: | ---: |
| Действующая биновая модель | 0,32776 | 0,28852 |
| Бустинг, только ветер 100 м, squared error | 0,32672 | 0,28479 |
| Бустинг, пять погодных величин, squared error | 0,30355 | 0,30120 |
| **Бустинг, погода + производные, squared error** | **0,26998** | **0,24369** |
| Бустинг, погода + производные, absolute error | 0,27139 | 0,20631 |
| Контроль: ветер + временные производные, squared error | 0,27844 | 0,22097 |
| Контроль: ветер + временные производные, absolute error | 0,27778 | 0,19669 |

Выбран `hgb_derived_squared_error`: снижение ошибки относительно baseline
**17,6% в декабре и 15,5% в январе**. Январская MAE 0,24369 означает около 24,4
процентного пункта нормализованной мощности, а не «точность 75,6%».
Улучшение присутствует для обеих турбин и обоих горизонтов.

Контрольные модели `wind_context` добавлены после первоначального сравнения,
поэтому исключены из выбора. Они используют только старую скорость ветра,
её среднее и изменение, час суток и дальность прогноза. В декабре расширенная
модель лучше такого контроля (0,270 против 0,278), в январе хуже (0,244 против
0,221). Следовательно, весь выигрыш нельзя приписать новым погодным величинам.
Одно добавление погоды без производных даже ухудшает январский результат
относительно baseline. Более низкая январская ошибка absolute-error моделей
сама по себе не основание выбирать их по этому месяцу задним числом.

Полные результаты всех девяти вариантов, MAE/RMSE/смещение по турбинам и
горизонтам, число примеров, границы обучения, версии библиотек и контрольные
суммы находятся в [`feature_experiment.json`](../data/processed/feature_experiment.json).

## Запуск

Из корня репозитория, в отдельном Python-окружении:

```bash
python -m pip install -r forecasting/requirements-experiment.txt
python -m forecasting.experiment_features
python -m unittest discover -s forecasting/tests -v
```

Все 92 погодных запуска включены в репозиторий; эксперимент выполняется офлайн.
При отсутствии кэша он завершится ошибкой. Загрузка явно вызывается отдельно:

```bash
python -m forecasting.feature_weather --start 2025-11-01 --end 2026-01-31
```

Эксперимент перезаписывает только `data/processed/feature_experiment.json`.
Он не меняет CSV, модель production, февральские ответы или контракт API.
Опциональная зависимость scikit-learn не добавлена в зависимости backend.

## Ограничения и следующий шаг

Январь уже использовался для анализа проекта: это ретроспективная проверка,
а не новый нетронутый тест. В объединённой MAE первые 24 часа входят в оба
горизонта; соседние запуски также повторяют целевые часы. Поэтому 4 296 декабрьских
и 4 338 январских оценок не являются независимыми наблюдениями. Доверительные
интервалы не оценивались; двух зимних месяцев недостаточно для вывода о сезонной
устойчивости. Фактической февральской мощности в данных нет, февральская точность
не заявляется.

Следующий шаг перед заменой модели API — сравнить расширенный вариант с
`wind_context` на последовательных недельных срезах внутри выданных датасетов,
с подбором параметров только на более ранних срезах. Оценивать нужно MAE,
смещение и поведение на малой/высокой мощности, затем зафиксировать одну
конфигурацию. Подключение потребует сохранения обученных моделей, расширенного
кэша для февральских запусков и повторной проверки всех 116 сценариев API.
