# Проверка ввода прогноза через ИИ — 23 сентября 2026

## Реализованный путь

«Спросить ИИ» → `/api/assistant/forecast-parameters` → проверенные параметры формы
→ тот же `/api/forecast-runs`, что при ручном вводе → `ForecastResult` с графиком,
таблицей, статистикой и происхождением погоды. Расчёт мощности выполняет существующая
модель forecasting. Графические компоненты и оформление сохранены.

Без указания турбины/горизонта применяются выбранные значения. Для неполной даты,
неподдерживаемого горизонта или невозможного времени запрашивается уточнение.
Часы из текста без пояса сохраняются без сдвига, как метки исходного датасета.

## Автоматические проверки

| Команда | Результат |
| --- | --- |
| `python -m unittest discover -s backend/tests -q` | 29 тестов пройдено, включая 13 новых тестов ИИ |
| `python -m unittest discover -s forecasting/tests -v` | 27 пройдено; 1 Windows-only тест пропущен на macOS |
| `cd frontend && npm test` | 8 тестов пройдено |
| `cd frontend && npm run build` | TypeScript и production-сборка Vite успешны |

Backend повторяет все 116 запусков февральского манифеста. Новые тесты сравнивают
полный ответ ручного и распознанного запроса на **22 февраля 2026, 17:00** для
обеих турбин и горизонтов 24/48 часов: все поля равны, кроме нового `run_id`.
Используется настоящее прогнозное ядро, архивный кэш и временная SQLite;
ответ OpenAI подменён только в автоматических тестах.

Проверены отсутствие ключа, отказы авторизации и лимита, таймауты, повреждённый
или незавершённый JSON, refusal, неподдерживаемые параметры и противоречивые ответы.
При ошибке разбора прогноз не вызывается и результат не сохраняется. Ответы
провайдера и ключ не показываются клиенту. Смещения вроде `+00:60` отклоняются
до Python-конвертации, чтобы не допустить неявного изменения часа.

## Настоящий OpenAI API и браузер

Локальный backend вызвал OpenAI Responses с `gpt-4o-mini` и реальным серверным
ключом. Фраза «22 февраля 17:00 2026 года» распознана как
`2026-02-22T17:00:00Z`. Ещё 7 сетевых проверок прошли: явный выбор турбины 2
и суток, английская и казахская формулировки, невозможное 31 февраля, 17:30,
неподдерживаемые 72 часа и отсутствующий год. Последние четыре дали уточнение.

В браузере на `http://127.0.0.1:5173` выполнено:

1. Ввод исходного примера через ИИ: форма заполнилась, график и таблица построились.
2. Повторный ручной запуск: **все 48 строк видимой таблицы полностью совпали**.
3. Очистка даты в ручной форме, затем тот же запрос через ИИ: корректная дата
   восстановилась, появился прогноз. До исправления пустая дата блокировала ИИ.

Для турбины 1, 48 часов: первая точка — `2026-02-22T18:00:00Z`, последняя —
`2026-02-24T17:00:00Z`, среднее на экране 0,414, минимум 0,222, максимум 0,781.
Дата запроса обозначает запуск; почасовые точки обозначают конец следующего часа.
Это значения модели, а не измерения за февраль: февральской фактической мощности
в исходных CSV нет. Проверка совпадения не является новой оценкой точности модели.

Ключ настроен только в локальном `.env` с правами `0600`; файл игнорируется Git
и Docker. Включаемые в Git файлы и сборка frontend проверены на отсутствие ключа.
HTTPS проверяет сертификаты через доверенный CA; проверка не отключалась.
Docker в этой проверке не запускался. На другом сервере нужно отдельно задать
`OPENAI_API_KEY`; содержимое локального `.env` не переносится через Git.
