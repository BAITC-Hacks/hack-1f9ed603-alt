# Правила работы в одной ветке

Цель проекта — воспроизводимый почасовой прогноз нормализованной мощности двух ВЭС на 24–48 часов. Сначала обеспечьте корректность прогноза во времени, затем улучшайте интерфейс.

## Владение папками

- `backend/`: API и интеграция, участник 1.
- `frontend/`: интерфейс, участник 2.
- `forecasting/` и `data/`: данные, архивная погода, модель, проверка, участник 3.
- `shared/`, `README.md`, `.env.example`, `compose.yaml`: общие файлы; согласуйте изменение с владельцами затронутых частей.

Не меняйте файлы чужой папки молча. Работая в одной ветке, чаще делайте небольшие коммиты и `git pull --rebase`. Не добавляйте чужие незакоммиченные файлы в свой коммит.

## Предметные ограничения

- Для каждого исторического запуска используйте только информацию, доступную в момент запуска. Храните время выпуска погодного прогноза и время прогноза выработки.
- Не заменяйте результат модели заготовленным ответом или моками. Если модель или погода недоступны, возвращайте понятную ошибку.
- Время CSV пока без подтверждённого часового пояса. Не присваивайте ему UTC неявно.
- Нормализованная мощность — не кВт·ч. Не называйте её абсолютной выработкой без известной номинальной мощности.
- Обрабатывайте пропуски и не допускайте пересечения обучающего и проверочного периодов.

Файлы `AGENTS.md` в папках содержат локальные правила. Актуальный контракт API — `shared/API.md`.
